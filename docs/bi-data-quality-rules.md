# BIデータ品質ルール

## 共通ルール

| 観点 | ルール | エラー時の扱い |
| --- | --- | --- |
| 文字コード | UTF-8のCSVとする。BOMは許容する | 読み込みを停止する |
| ヘッダー | 定義済みの列が過不足なく存在する | 読み込みを停止する |
| 日付 | `YYYY-MM-DD`形式とする | 読み込みを停止する |
| 金額・工数・単価・進捗 | 0以上の数値とする。進捗率は100以下とする | 読み込みを停止する |
| 真偽値 | `true`又は`false`の小文字とする | 読み込みを停止する |
| 一意性 | 各CSVの定義済みキーは重複させない | 読み込みを停止する |
| 参照 | ファクトの`project_id`は`projects.csv`に存在する。工数の`resource_id`は`resources.csv`に存在する | 読み込みを停止する |

## 業務ルール

- 予定開始日は予定完了日以前、実績開始日は実績完了日以前にします。
- 未完了の作業・節目は実績完了日を空欄にします。
- WBSスナップショットの進捗は、同じ基準日で同じ作業を複数行にしません。
- 予算はプロジェクト、月、費目の組合せを一意にします。異なる通貨の金額を同じファイルに混在させません。
- 単価は役割ベースで管理し、同じリソースの適用期間を重複させません。各工数計上日に適用可能な単価が必ず1件必要です。
- 人件費は、計画工数×計画時間単価、実績工数×実績時間単価でETL時に算出します。入力CSVへ手入力しません。
- 課題・リスクの状態と解決日の矛盾は運用で防ぎます。解決済みに変更する際は解決日を記録します。

## 監視と是正

ETLの例外メッセージを修正対象の特定に用います。意図的な値の除外や0への置換は行いません。欠損に業務的な意味がある列はNULLとして保持し、KPIの分母が0になる場合はNULLを返して画面では「—」と表示します。

## 機密情報の扱い

サンプルには実在する組織名、顧客名、個人名、連絡先、認証情報を入れません。実データへ置き換える場合も、アクセス権限、保存場所、保持期間、匿名化方針は利用組織の規程に従います。
