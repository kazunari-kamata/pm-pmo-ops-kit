# RAIDと変更管理ガイド

RAIDは Risks（リスク）、Assumptions（前提）、Issues（課題）、Dependencies（依存関係）を一元的に扱う方法です。このリポジトリでは、変更要求と意思決定も同じ管理台帳で参照できるようにしています。

## 登録時の確認

1. 事実と推測を分け、発生日または検知日を記録します。
2. 影響を範囲・品質・費用・日程・体制の観点で評価します。
3. 担当者と次の確認日を決めます。
4. 期限を超える場合のエスカレーション先を決めます。
5. クローズ時は、対応結果と再発・再検討の要否を残します。

変更要求は、影響評価前に実施を約束しません。緊急変更であっても、事後評価の期限と承認者を記録します。
